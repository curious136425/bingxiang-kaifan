# 冰箱开饭 · 可交互原型

> 冰箱里有什么，今晚就做什么。

这是一个基于“现有食材 + 想吃的口味”推荐菜谱的高保真 Web App 原型。它不是静态设计稿，食材增减、实时打分、排序筛选、收藏、购物清单、份量换算、分步教程和计时器都可以实际操作。

## 最快体验

直接双击：

```text
dist/index.html
```

这是一个已经内联所有代码和样式的单文件页面，不需要安装依赖，也不需要联网。

也可以双击根目录的 `打开原型.cmd`。

## Android 安装包

最新版为 v1.2，包含 100 道菜及完整图片资源。APK 放在 GitHub Releases，源码仓库不提交二进制安装包和构建缓存。

本地构建需要 JDK 21 与 Android SDK，然后运行：

```bash
pnpm android:apk
```

生成文件位于 `android/app/build/outputs/apk/debug/app-debug.apk`。

## 已实现

- 输入或快捷选择现有食材，自动识别“西红柿 → 番茄”“马铃薯 → 土豆”等常用别名
- 多选口味、限制用时、只看素食、设置基础调料是否齐全
- 根据食材覆盖、口味、时间、难度、临期食材和评分实时排序
- 每张推荐卡展示匹配度、缺少的核心食材和可解释推荐理由
- “只看无需补主料”“最快出锅”“缺料最少”等筛选与排序
- 100 道结构化家常菜谱，包含数量、替代食材、火候、计时和关键技巧
- 支持按菜名或食材搜索；输入菜名会直接筛出相关菜谱，不会误当成冰箱食材
- 每道菜均配成品图和逐步教程图，AI 生成图片在界面中明确标注为示意图
- 菜谱详情支持 1～6 人份动态换算
- 缺少的食材一键加入购物清单
- 一步一屏的烹饪模式，支持步骤进度、计时器、语音按钮演示和中断续做
- 收藏、冰箱库存、临期标记、购物清单与烹饪进度使用 `localStorage` 保存
- 桌面端与手机端响应式布局

## 推荐逻辑

首版不用大模型做排序，采用稳定、可测试、可解释的确定性评分：

```text
总分 100
├─ 食材匹配 50：核心主料权重 3，普通配料权重 1
├─ 口味匹配 20：与用户所选口味标签的覆盖率
├─ 时间匹配 12：超出期望用时后逐步扣分
├─ 难度匹配 8：按用户厨艺等级匹配
├─ 临期优先 5：优先消耗标记为“优先吃”的食材
└─ 菜谱评分 5：用作同分排序信号
```

同分时依次比较：缺少核心食材数、缺少食材总数、烹饪时间、菜谱评分。

核心代码：

- `src/recommendation.ts`：食材归一、评分和排序
- `src/data.ts`、`src/recipesBatchA.ts`～`src/recipesBatchD.ts`：100 道结构化菜谱与食材目录
- `src/App.tsx`：完整产品流程与交互
- `src/recommendation.test.ts`：推荐逻辑单元测试

## 从原型到正式产品

建议按下面的边界演进：

```text
React / App
  ↓
Recommendation API
  ├─ 食材别名与库存归一
  ├─ 确定性候选召回与评分
  └─ 个性化重排
  ↓
Recipe Service + PostgreSQL
  ├─ 菜谱、食材、单位、步骤
  ├─ 用户库存、偏好、过敏项
  └─ 收藏、计划、购物清单
```

优先级建议：

1. 继续人工复核菜谱数据，并补充过敏原与食品安全字段。
2. 增加账号与跨设备同步，后端可用 FastAPI / NestJS + PostgreSQL。
3. 增加图片识别，拍冰箱后让用户确认识别结果，再写入库存。
4. 用用户的点击、收藏和完成功能做个性化重排。
5. 大模型只负责自然语言食材归一、替代建议和教程解释；火候、时间与食品安全信息仍来自审核过的结构化菜谱。
